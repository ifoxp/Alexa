# Alex

Голосовий асистент для Windows зі здібностями, які підключаються на льоту.
Кажеш ключове слово, просиш щось звичайною мовою — модель вирішує, який із
~17 плагінів має це виконати.

Сам асистент на Python, два застосунки налаштувань на C#. Збирається в
готовий exe з іконкою в треї.

## Що вміє

Керування вікнами й моніторами, гучність окремих програм, медіа, зір по
екрану, пошук новин і в інтернеті, читання календаря, розваги й підбір
фільмів, автоматизація клавіатури, моніторинг системи, а також плагін із
графіками відключень світла.

Кожне з цього — плагін. Додати новий означає покласти файл у `plugins/`,
ядро асистента не змінюється.

## Шлях одного запиту

1. **Porcupine** розпізнає ключове слово офлайн, тож нічого не надсилається,
   поки ти справді не звернувся
2. Аудіо йде в розпізнавання мовлення
3. **Gemini** отримує текст разом з усіма плагінами у вигляді function
   declarations і обирає, що викликати
4. Плагін виконується, асистент озвучує результат

## Два механізми, які варто пояснити

### Говорити ще до того, як робота зроблена

Кожен плагін автоматично перетворюється на `FunctionDeclaration` для Gemini.
Поруч із ними стоїть один синтетичний інструмент —
`speak_response(text, is_command, transcript)` — і модель має інструкцію
**завжди викликати його разом** зі справжньою командою.

Читач стріму крутить блокуючий SDK-стрім в окремому потоці, складаючи шматки
в `asyncio.Queue`. У момент, коли приходить частина `speak_response` — ще до
кінця стріму і до того, як плагін почав виконуватись — спрацьовує колбек
`on_speak_ready`, і синтез мовлення починає говорити.

Виходить, що один запит до моделі дає і фразу-підтвердження, і дію, причому
підтвердження чути, поки дія ще розбирається й виконується. Асистент
відповідає одразу, а не мовчить весь конвеєр.

### Плагіни, що самі ставлять свої залежності

Плагін, покладений у `plugins/`, може імпортувати щось невстановлене. Замість
того щоб впасти, `smart_plugin_manager.py` виправляє ситуацію:

1. Ловить `ImportError` і дістає з нього назву модуля
2. Проганяє через таблицю аліасів — `win32gui` не пакет, пакет це `pywin32`
3. Знаходить **системний** Python, що нетривіально під PyInstaller, де
   `sys.executable` вказує на `Alex.exe`
4. Ставить із `CREATE_NO_WINDOW`, щоб користувачу не блимнуло чорне вікно
5. Запускає `pywin32_postinstall`, коли цьому пакету треба зареєструвати DLL
6. Підмішує системні site-packages у `sys.path` і повторює імпорт

У підсумку користувач може додати сторонній плагін, і той запрацює з першого
разу, без «відкрийте термінал і виконайте».

## Інтерфейс плагіна

Плагін успадковує `SmartPlugin` і оголошує назву, однорядковий опис для
моделі й словник команд. Опис важливіший, ніж здається — саме його читає
модель, вирішуючи, чи цей плагін підходить під запит.

```python
class MyPlugin(SmartPlugin):
    @property
    def name(self) -> str: ...

    @property
    def description(self) -> str: ...   # 1-2 речення, їх читає модель

    @property
    def commands(self) -> Dict[str, str]: ...
```

## Застосунки налаштувань

Два окремі фронтенди на C#: старіший на WinForms і новіший на WinUI 3 з
сіткою іконок для керування плагінами. Обидва правлять ту саму локальну
конфігурацію, яку читає Python.

## Налаштування

Ключі лежать у локальному `config.json`, який у `.gitignore` — ключ Picovoice
для ключового слова і ключ Gemini. Асистент відмовляється стартувати на
значеннях-заглушках, замість того щоб упасти пізніше з незрозумілою помилкою.

## Збірка

```bash
pip install -r requirements.txt
python main.py          # запуск із сирців
python build.py         # збірка через PyInstaller
```
